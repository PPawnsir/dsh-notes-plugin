筛选中心 · 设计说明（落地口径）

design/notes-filter-center.html · 2026-10-02 · 供 notes-filter-center 开发实施 · 数据为内存 mock · token/图标/风格与 design/notes-ui-v2.html 一致

1筛选按钮（「筛选(N)」）

  • 位置：侧栏搜索框正下方 —— 即 v2 .chips 行的原位。
  • 常态：中性药丸按钮（--nbg-raise 底）；存在激活条件 或 面板打开时高亮（--nbg-sel + --nacc-tx）。
  • 计数：激活条件数 N > 0 时，按钮内显示蓝色计数丸（状态组 + 类型组条件合计）。
  • 图标：漏斗 i-filter（沿用 v2 图标体系；调研笔记中的 ⚙ 为占位符，避免与 side-foot「设置」齿轮混淆）。
  • 点击 = 开关 popover；aria-expanded 同步。

2激活条件 chips

  • 紧随筛选按钮右侧，每个激活条件一条 chip：条件图标（状态组）/ kind 色点（类型组）+ 文案 + ×。
  • × = 单条移除；chips 与 popover 勾选实时双向同步；单行横排、超宽横向滚动（硬性布局约束：不换行、不挤压树区高度）。
  • 演示见场景 B（已注入 + 决策 两条）与场景 D（置顶 + 敏感 两条）。

3popover 分组面板

  • 锚定筛选按钮左对齐下挂，覆盖于列表之上；点外部 / Esc / 「完成」关闭；面板内点击不关闭。
  • 两组：状态（置顶 / 已注入 / 曾注入 / 敏感，各带图标）+ 类型（笔记 / 决策 / 待办 / 链接 / 引用，kind 色点）。
  • 语义：组内多选 = OR，跨组 = AND；勾选即时生效（列表、chips、按钮计数、底部命中数同步刷新）。
  • 每选项右侧计数 = 该条件单条件命中数（示意，帮助预判结果量）。
  • 底部：命中 N 条 实时预览 + [清空]（清全部条件，面板保持打开）+ [完成]（关闭面板）。
  • 「曾注入」口径：当前未注入但历史注入过（mock 字段 everInjected；实现端数据源 = 注入历史遥测，由 notes-filter-center 与 host 对齐）。当前已注入的笔记不匹配「曾注入」。

4独立排序控件（↕ 时间 / 引用 / 相关度）

  • 筛选行右端独立按钮：↕ + 当前排序名；点击弹单选菜单（勾选标记 + 说明文字）。
  • 排序与筛选正交：改排序不动条件，改条件不动排序。
  • 时间 = 置顶优先 + 更新降序（即 v2 缺省 host 序）；引用 = useCount 降序（v2「按引用」chip 迁入）；相关度 = 搜索打分（本稿以 useCount×2 + 注入/置顶加权 mock 示意，实现端接搜索 score）。
  • 非缺省排序（或菜单打开）时按钮高亮提示。

5笔记行徽章带

  • 标题行下方第二行为徽章带；无徽章不渲染该行（行保持单行紧凑）。
  • 顺序固定：置顶 → 敏感🔒 → 已注入 → 曾注入⏱ → 被引用 N。
  • 配色：置顶 = --nwarn；敏感 = --ndanger；已注入 = --nacc-tx + --nbg-sel 底（已注入/曾注入互斥）；曾注入、被引用 = --nt3 中性。
  • 全部徽章带 tooltip（hover 查看，如「被 Agent 引用（note_get 命中）N 次」）；被引用 0 次不渲染。
  • 徽章带吸收 v2 行内的 inject bolt 与 use 徽章，视觉统一为一套 pill 语言。

7交互细节

  • Esc 关闭顺序：排序菜单 → 筛选面板（均不干扰 v2 全局 Esc = 退出多选）。
  • 面板打开时筛选按钮保持高亮（aria-expanded="true"）。
  • 搜索框与筛选条件叠加 = AND（本稿已接线，可直接输入验证）。
  • 空结果态：提示 + 「清空筛选条件」快捷链接。
  • 浮层动画：120ms 上飘淡入（popIn）；暗/亮双主题经顶部「切换主题」验证。
